## Affected Pages/Routes

- `POST /admin/purchase/orders/:id/receive` — PO receipt with stock update + audit log
- `POST /admin/fulfillment/orders/:id/pick` — start picking (pending → picking)
- `POST /admin/fulfillment/orders/:id/pack` — confirm pack (picking → packed)
- `POST /admin/fulfillment/orders/:id/dispatch` — dispatch (packed → dispatched)
- `GET /admin/fulfillment/orders/:id` — fulfillment status detail
- Medusa admin dashboard (/app) — Aurelia dashboard tiles (avg lead time, stuck-in-picking count)

## Key Interactions to Verify

- Receive a submitted PO → inventory level increments AND StockAdjustmentLog record created
- Receive a submitted PO where log write fails → inventory level NOT changed (compensation fires)
- Receive a draft PO → 400 "must be submitted"
- Receive an already-received PO → 400
- Full fulfillment happy path: pending → picking → packed → dispatched
- Dispatch idempotency: second dispatch call on already-dispatched order → 409 (DB constraint)
- Dispatch a cancelled order → 400 (status guard)
- Low-stock notification fires when stock drops below threshold
- Low-stock notification suppressed (not propagated) when notification module throws
- Packed-not-shipped job fires notification for orders packed >24h
- Packed-not-shipped job does NOT re-notify within 4-hour cooldown window
- Customer service role can GET /admin/fulfillment/* but NOT POST
- Inventory role can POST /admin/fulfillment/*
- Purchasing role cannot access /admin/fulfillment/*

## Edge Cases

- Receive PO with variant that has no linked inventory_item → skip gracefully (no crash)
- Concurrent dispatch requests on same packed order → only one succeeds (DB unique constraint on order_id)
- pick-list generation with 0 line items → WorkflowStepError 400
- confirmPack with weight=0 → Zod validation 400
- dispatchOrder with empty tracking string → Zod validation 400
- StockAdjustmentLog with invalid reason_code → Zod 400
- packed-not-shipped job: no qualifying orders → no notifications sent, job completes cleanly
- packed-not-shipped job: DB query fails → logger.warn, job does not throw

## Critical Paths

- PO receive → stock increment → audit log (must succeed atomically or both roll back)
- Order placed → pick → pack → dispatch (full fulfillment lifecycle, end-to-end)
- Low inventory event → purchasing team notified within one Medusa event cycle
- Packed order stuck 24h → inventory team notified, cooldown prevents spam
